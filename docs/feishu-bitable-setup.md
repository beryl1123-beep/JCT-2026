# 第四幕萤火数据库：飞书多维表格配置

## 一、创建方式

1. 登录飞书并进入“多维表格”。
2. 选择“新建多维表格”，不要导入 Excel/CSV。
3. 将多维表格命名为“JCT-20 萤火星河”，数据表命名为“萤火内容”。
4. 按下表逐项创建原生字段，保证后续可以直接编辑和写入。

## 二、字段类型

| 字段 | 飞书字段类型 | 网页用途 |
| --- | --- | --- |
| 微光标题 | 单行文本，主字段 | 可选；卡片标题，最多 32 字；留空时网页标题区域保持空白 |
| 内容类型 | 单选：`纯文字`、`网址` | 必填；网址类型额外显示网页链接 |
| 微光正文 | 多行文本 | 必填；祝福正文，最多 500 字 |
| 网页链接 | 超链接 | 内容类型为“网址”时必填 |
| 是否审核通过 | 单选：`待审核`、`✓ 已通过`、`× 未通过` | 必填；只有“✓ 已通过”可展示 |
| 署名 | 单行文本 | 可选；留空或只填写空格时，网页显示“一位路过的炭火” |
| 提交来源 | 单选：`网站投递`、`后台录入` | 可选；记录内容来源 |
| 创建时间 | 创建时间 | 自动生成；决定上一张与下一张的顺序 |

## 三、网页与飞书的字段映射

```text
微光标题      -> title
内容类型      -> type（纯文字=text，网址=website）
微光正文      -> content
网页链接      -> url
署名          -> signature
是否审核通过  -> reviewStatus
创建时间      -> createdAt
飞书记录 ID   -> id
```

读取规则：只返回 `是否审核通过 = ✓ 已通过` 的记录，并按“创建时间”从早到晚排列。用户点击任一荧火时随机抽取一条；“上一张”和“下一张”只在已通过内容列表中循环展示，不显示当前序号或总条数。

投递规则：网页提交的记录写入飞书时，默认设置为 `是否审核通过 = 待审核`、`提交来源 = 网站投递`，由阿林Art在飞书中选择“✓ 已通过”后才会展示。飞书表单中的“微光标题”需关闭必填校验。

## 四、安全连接方式

静态网页不能保存飞书应用密钥。正式连接需要一个受保护的数据接口：

```text
浏览器页面
  -> /api/fireflies（读取已发布内容、接收新投递）
  -> 飞书开放平台 API
  -> “JCT-20 萤火星河”多维表格
```

接口部署时需要以下环境变量，不能写入 GitHub 仓库：

```text
FEISHU_APP_ID
FEISHU_APP_SECRET
FEISHU_BITABLE_APP_TOKEN
FEISHU_BITABLE_TABLE_ID
```

## 五、建表完成后需要的信息

完成建表后，复制浏览器地址栏中的完整多维表格链接。链接通常包含：

- `base` 后面的多维表格 `app_token`
- `table=` 后面的数据表 `table_id`

下一步还需要在飞书开放平台创建企业自建应用，给应用开通多维表格读写权限，并把该应用添加为这张表的协作者。应用密钥只配置在服务端环境变量中。
